# RenovAlte — Smart Renovation & Financing Assistant for Germany

> Renovating a home in Germany is paperwork-heavy: KfW funding programs, GEG/EnEV building standards, Bundesland-specific permits, finding the right Handwerker, comparing offers in three different formats. RenovAlte is the assistant I built to make that whole journey feel like one app instead of twelve browser tabs.

It plans the project, suggests financing, finds contractors nearby, sends them invitations through your own Gmail, reads their replies, and compares the offers side by side — all driven by RAG over real German renovation documents (KfW programs, GEG standards, permit rules) so the advice is grounded, not made up.

---

## What it does

RenovAlte walks a homeowner through six stages of a renovation, end to end:

**1. Planning** — A wizard collects the project scope (kitchen, bathroom, roofing, HVAC, etc.), location, budget. The backend builds a structured renovation plan with phases, a Gantt-style timeline, a permit checklist, and a budget preview. The plan is generated by Gemini with a RAG retrieval step over a knowledge base of German building documents.

**2. Financing** — Pulls KfW programs and conventional financing options that match the project. The recommendation engine is a separate RAG service backed by a curated PDF corpus (KfW program docs, budget estimation guidelines).

**3. Contracting** — Imports the plan, finds matching contractors near the address via the Google Places API v1, lets the user pick a shortlist, then sends personalised invitation emails through the user's Gmail account (OAuth). A background worker monitors the inbox for replies, parses offer documents (PDFs included), and produces an AI analysis report so the user can compare contractors on price, scope, and risk.

**4. AI Companion** — A persistent chat assistant that has context on the active project and can answer questions like "do I need a permit for this in Bavaria?" or "what's the difference between KfW 261 and 297?".

**5. Reporting** — Every step writes back to the project, so the homeowner ends up with a paper trail: generated plans, contractor conversations, offer analyses, PDF exports.

## Tech stack

**Backend** — Django 5.2, Django REST Framework, Django Q2 (background jobs for email monitoring), SQLite in dev. Vector search runs on **ChromaDB** and **Qdrant**, embeddings via `sentence-transformers`. LLM calls go to **Google Gemini** for text and **Vertex AI Imagen** for image generation. Google Places v1, Gmail API (OAuth + IMAP fallback), Google Cloud Storage for assets.

**Frontend** — React 19 + TypeScript, Tailwind CSS, the full Radix UI primitive suite, Tiptap for the rich-text editor, Framer Motion for transitions, Recharts for budget visualisations, react-router v7. State is split across three contexts (Auth, Project, AppState). `react-hook-form` for the wizard forms.

**Integrations** — Gmail OAuth 2.0, Google Places API v1, Google Vertex AI, Google Gemini, KfW knowledge base (custom PDF ingestion pipeline).

## Highlights I am proud of

- **Two RAG pipelines** running side by side — one for planning (renovation phases, permit rules), one for financing (KfW programs). Different corpora, different retrieval tuning, same underlying infra.
- **Inbox-to-insight contractor loop.** The user clicks "send invitations", the app authenticates against their Gmail, sends personalised emails, and a Django Q2 worker watches the thread. When a contractor replies, the system pulls the message, parses any PDF offer attached, and runs an analysis pass with Gemini. The homeowner gets a comparison table without ever opening Gmail themselves.
- **Domain-grounded.** The knowledge base is not generic — it is six curated German PDFs: GEG/EnEV building standards, KfW financing, renovation phases, Bundesland permits, materials planning, budget estimation. The AI's answers cite from this corpus.
- **A real design system.** Every form, dialog, dropdown, tooltip in the app is built on Radix primitives with Tailwind styling — accessible, keyboard-navigable, consistent.
- **Project-scoped state.** Everything in the authenticated app is bound to the selected project, so a user can run multiple renovations in parallel without context bleeding between them.

## Getting it running locally

You need Python 3.11+, Node 18+, and a Google Cloud project with the Gemini, Vertex AI, and Places APIs enabled.

### Backend

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
cp .env.example .env             # fill in your keys, see below
python manage.py migrate
python manage.py runserver
```

### Frontend

```bash
cd frontend
npm install
npm start
```

### Windows one-liner

If you are on Windows, the script in the repo root starts both servers in the same terminal:

```cmd
run-dev.bat
```

### Environment variables

Open `backend/.env` and set:

```env
GEMINI_API_KEY=...                 # Google AI Studio key, for text generation
GOOGLE_PLACES_API_KEY=...          # Google Cloud key with Places API v1 enabled
GOOGLE_CLOUD_PROJECT_ID=...        # for Vertex AI Imagen
GOOGLE_CLOUD_LOCATION=us-central1
VERTEX_AI_IMAGEN_MODEL=imagen-3.0-generate-001
```

Gmail OAuth credentials are configured separately under `backend/data/` — see `.env.example` for the full list of optional variables.
